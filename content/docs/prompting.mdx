Most films are written by agents. You describe the film. An agent asks for the details it lacks, writes a brief, shows stills, and then writes `page.html`. Agents in this repo read `AGENTS.md`, so they already know the page contract and the house rules. Your job is the vision.

## Start from a template

The repo has a template per film type in `prompts/`. `guides/ROUTING.md` lists them and maps a request to one.

| Template | Use when |
|---|---|
| `showreel-one-liner` | no brief, a taste probe |
| `brand-launch-from-url` | a real product from a URL, with its own kit and real captures |
| `ui-morph-loop` | one element becomes 8 to 12 UI states and loops |
| `reference-rebuild` | a reference mp4 must be matched |
| `directors-brief-long-form` | over 60 s, or more than one session |
| `story-explainer` | explain a topic with invented visuals |
| `music-video-beat-synced` | a song exists, and every cut lands on a downbeat |
| `beat-sheet` | any film over one beat: the shot table before code |
| `interactive-lab-capture` | a mechanism as a working model, then a scripted tour of it |
| `production-brief-acceptance` | a client brief with claims that someone other than the author must sign off |
| `pixel-art-sprite` | a 16-bit sprite loop on a logical canvas |

`prompts/` holds 11 templates in all. Start a film from one:

```bash
bin/vawe new my-launch --from prompts/brand-launch-from-url.md
```

The command checks which details the request leaves open. There are six: subject, message and show (required), then format, assets and ending (optional). While a required detail is open, the command prints each open detail with its reason and an example, and writes nothing. Answer in a file and pass it with `--answers <file>`, or give one answer with `--detail key=value`. An agent can run `--questions-json` to get the questions as `AskUserQuestion` calls. For an unattended run, pass `--defaults`. It guesses each open detail and marks the guess `(guess: change me)`.

## The brief is measured

`bin/vawe new` writes `brief.md` in a measured shape. A number that a program can measure is a number. A value that it cannot measure yet is a guess, marked `(guess: change me)`. The agent replaces each guess with a measured value or its own choice. The sections come in this order:

1. **Inputs.** The questions of the template, each with its default marked `[unanswered: default taken]`.
2. **Task.** What the film is, who sees it, the message and the spectacle second.
3. **Taken from.** Four to six reference frames, with what each one gives.
4. **Directions.** Three directions from three families (type, object, graphic). The agent picks one and says why.
5. **Signature.** Six dials: band, ease, stagger, seam, palette and thread. The page repeats them in `<meta name="signature">`.
6. **Look.** Numbers, not adjectives: colours, the typeface, type as a fraction of frame height.
7. **Design system and kit.** Palette roles, type, and the ground layers.
8. **States.** One static key frame per world, built from the kit before any motion.
9. **Ideas.** A table with four ideas for each beat and cut, and the pick with its reason.
10. **Board.** A plan for time: rhythm, a named move per cut, and the sound.
11. **Motion pass.** One row per cut, after the draft.
12. **Spec.** Three tables, in seconds and percent of frame: shots, words and objects.
13. **Acceptance.** Targets for the checks, with the measured value next to each one.
14. **Gates, Pitfalls and Deliver.** The order of the stills, the draft loop and the final, the pitfalls, and the files to hand over.
15. **First draft.** The taste list to read and the `bin/vawe dev` command.

The slowest beat is at least 3 times the fastest. For the page contract, see [The page](/docs/the-page).

A short prompt can work. What helps most is a reference or a genre anchor, and a ban list. A default you do not exclude is free for the agent to use.

## What the agent does next

The agent writes the beat table, then shows three directions as stills in `directions.html`. You pick one. Then it renders a draft with `bin/vawe dev <page>`. See the loop in [Quickstart](/docs/quickstart).

## Inputs that raise quality

- A real product URL, crawled, not invented. See [Brand reflection](/docs/brand-reflection).
- A reference film. `bin/vawe see <ref.mp4> --spec` measures it into `SPEC.md`. Mark each line KEEP or CHANGE, then rebuild.
- Real data. Numbers and copy are true and looked up, never made up for effect.
- The film type, if you know it. It saves a routing step.

## What to avoid

- Do not ask for fake product UI. A screen, logo or photo in the plan must trace to a real capture.
- No em dash in on-screen copy. The validator rejects it.
- Do not name hex codes or easings to fix a weak film. Fix the anchor and the ban list.

## What to say when it is wrong

Name the symptom, not the cause. "Beat three reads as a slide, nothing moves but the text" is better than "make it more dynamic". The agent can find the cause. It cannot guess what you saw.

To change direction instead of fixing a detail, change the anchor and the ban list.
